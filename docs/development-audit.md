# Abhängigkeitsprüfung am 01.11.2026

`npm run audit:release` verlangt weiterhin **null bekannte Laufzeit-Schwachstellen**. Für den gesamten Entwicklungsbaum wird genau ein geprüfter Hinweis zugelassen: [GHSA-g3hv-75wg-m249 / CVE-2026-118764](https://github.com/advisories/GHSA-g3hv-75wg-m249). Die Registry meldet diesen inzwischen für sämtliche minimatch-Versionen unter 11.0.1 einschließlich der transitiven ESLint-/TypeScript-Werkzeuge. Ein unverändertes `npm audit` meldet deshalb 21 moderate Befunde im Entwicklungsbaum; dies sind nicht 21 unterschiedliche Laufzeitlücken.

Der beschriebene Verstärkungsweg benötigt vom Angreifer gelieferte Globmuster und `optimizationLevel >= 2`. Die installierten Legacy-v3-Matcher enthalten diesen Optimierungspfad nicht; die neueren Matcher verwenden standardmäßig Stufe 1. Unsere Entwicklungsprüfungen verarbeiten lokale, im Repository definierte Quellpfade. minimatch und diese Lint-Abhängigkeiten werden nicht in das Plugin gebündelt und erhalten keine Vault-Inhalte. Dies ist eine begründete Ausnahme für den Entwicklungsprozess, keine Behauptung, der Upstreamhinweis sei allgemein behoben.

Ein pauschaler Override auf minimatch 11 würde unter anderem die von den Legacy-Verbrauchern erwartete direkt aufrufbare CommonJS-Schnittstelle ändern. Deshalb wird kein ungeprüfter Hauptversionswechsel erzwungen. Sobald kompatible Upstreamabhängigkeiten beziehungsweise Backports vorliegen, soll die Ausnahme entfallen.

`scripts/audit-review.mjs` erlaubt ausschließlich die konkrete Advisory-URL mit moderater Schwere, deren abhängige Pakete und ausschließlich im Lockfile als `dev: true` markierte Installationen. Laufzeitpfade, neue Advisories, höhere Schwere, unbekannte Abhängigkeitskanten oder fehlerhafte Registryantworten lassen die Prüfung scheitern. `tests/unit/audit.test.mjs` prüft diese Grenzen. Die vollständigen Registryberichte bleiben unter `test-results/audit.json` erhalten. CI und Release verwenden denselben Gate; der rohe `npm audit`-Befund wird hier ausdrücklich dokumentiert.
